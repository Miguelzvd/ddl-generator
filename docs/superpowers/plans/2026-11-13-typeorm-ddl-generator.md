# TypeORM → DDL Oracle — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Página 100% no navegador que lê entities TypeORM (pasta ou arquivos), lista cada uma com status e gera DDL Oracle comentado.

**Architecture:** Núcleo puro e testável (`parser` → `analysis` → `ddl`) sem DOM; UI em TypeScript sem framework consome o núcleo. Build único `dist/index.html` via vite-plugin-singlefile.

**Tech Stack:** Vite 5.4.21, TypeScript 5.6.3 (também runtime do parser), vite-plugin-singlefile 2.3.4, Vitest 2.1.9, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-13-typeorm-ddl-generator-design.md`

## Global Constraints

- Nada é enviado para fora da máquina; sem servidor; `dist/index.html` abre via `file://`.
- Só TypeORM; só Oracle.
- Todo valor presumido sai no SQL como `-- ATENÇÃO: <motivo>`.
- `VARCHAR2` sem tamanho → `VARCHAR2(255)` + aviso.
- `@PrimaryGeneratedColumn` → `NUMBER GENERATED BY DEFAULT AS IDENTITY`; opção 11g → `CREATE SEQUENCE <schema>.SQ_<TABELA>` e nomes de constraint truncados a 30 (padrão: 128).
- Constraints: `PK_<TABELA>`, `FK_<TABELA>_<COLUNA>`, `IX_<TABELA>_<COLUNAS>`.
- Status: `ok` (Pode gerar), `assumptions` (Pode gerar, com suposições), `commented` (Comentado), `impossible` (Não é possível gerar).
- Textos da UI em português.
- Commits: o usuário faz os commits (skill `commit`); o executor não roda `git commit`.

## Review Focus

1. FK cujo tipo da coluna difere da PK de destino (ex.: `ID_CATEGORIA varchar2` → PK `NUMBER`) → FK comentada com motivo (ORA-02267), status `assumptions`. Teste em Task 3.
2. Arquivo inteiro comentado (`LogAcesso.ts`) → aparece como `commented` com nome da tabela extraído. Teste em Task 2.
3. Relação para entity não carregada ou para view → FK comentada, nunca emitida ativa. Teste em Task 3.
4. Arquivo com sintaxe que não define entity / erro de leitura → linha `impossible`, demais seguem. Teste em Task 2/3.
5. Aspas simples em comentários (`COMMENT ON ... IS '...'`) → escapadas (`''`). Teste em Task 4.

### Task 3: Tipos, plano de tabela e classificação

**Interfaces:** `mapColumnType(col: ColumnModel): { sql: string; warning?: string }`; `planTable(e: EntityModel, registry: Map<string, EntityModel>, opts: GenerateOptions): TablePlan`; `buildReports(files: ParsedFile[]): { reports: EntityReport[]; registry: Map<string, EntityModel> }`.

- [ ] Testes `tests/plan.test.ts`:
  - `varchar2` sem length → `VARCHAR2(255)` + warning; com length 10 → `VARCHAR2(10)`; `timestamp` → `TIMESTAMP`; `date` → `DATE`; sem tipo + tsType `number` → `NUMBER`; `boolean` → `NUMBER(1)`; tipo `xpto` → `XPTO` + warning.

  - Diretores sozinho: FK com motivo "não foi carregada".
  - PedidoV: status `impossible` (view).
  - Categoria: status `assumptions` (VARCHAR2 sem tamanho). Cliente: `ok`.
  - LogAcesso: `commented`. `ParsedFile` com `error` → `impossible` com o erro no motivo.

### Task 4: Gerador DDL

**Interfaces:** `generateDdl(reports: EntityReport[], registry, opts, source: string): string` (gera só reports `selected`; views listadas no fim).

- [ ] Testes `tests/generate.test.ts`:
  - Contém `CREATE TABLE LOJA.CLIENTE (`, `CONSTRAINT PK_CLIENTE PRIMARY KEY (ID_CLIENTE)`, `DEFAULT SYSDATE`, `NOT NULL` em `ATIVO`.
  - `ID_PRODUTO NUMBER GENERATED BY DEFAULT AS IDENTITY`; com `oracle11g` → `CREATE SEQUENCE SQ_PRODUTO` e sem `IDENTITY`.

  - Comentário com `'` vira `''`. Nome > 30 com 11g é truncado.
